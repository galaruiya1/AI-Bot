# 偏高频做市策略评分

对象：Hummingbot `master` 上这 8 个策略（V1 `pure_market_making` 与 V2 `pmm_v1` 分开计）。依据是源码能力，不是宣传文案。

时钟上限不变：策略逻辑最快 **0.1s/轮**（默认 1s）。下面的「高频」都指这个范围内的秒级盘口做市，不是托管机房微秒 HFT。

## 评分机制

每项 0–10。加权总分 = Σ(分 × 权重)，再 ×10，得到 **0–100**。

| 维度 | 权重 | 看什么 |
| --- | --- | --- |
| A 高频贴合 | 20% | 定价是否吃实时盘口（而非 K 线）；默认刷新能否压到秒级；有无 tick / 价距刷新；会不会无脑全撤重挂 |
| B 库存控制 | 20% | 目标库存、skew、区间、再平衡、单边网格是否会单边堆积 |
| C 风控 | 20% | 止盈止损、时间屏障、成交冷却、价格带、盈亏平衡保护、全局 TP/SL |
| D 定价执行 | 15% | 多层、动态价差、刷新容差、盘口优化、maker 属性、网格密度 |
| E 生产成熟度 | 15% | 官方是否当实盘示例、V2 可热更新、可观测性、是否仍维护 |
| F 可运维 | 10% | 参数是否可理解；过简则脆，过繁则难调 |

**刻度**：0 无此能力；3 有雏形；5 能用；7 完整；9–10 该类里最强。

加权总分衡量「能不能当秒级做市底盘」，不是回测收益率。

## 分项说明

### `simple_pmm` — 36

教学脚本（94 行）。每 `order_refresh_time`（默认 15s）**全撤再挂** 一买一卖，参考中间价或最新成交价。`budget_checker` 不够钱就整组不下。

- A6：吃实时价，刷新可压，但无容差、无 tick 对齐，全撤成本高。
- B1 / C1：无库存、无止损止盈、无成交冷却。
- D3：单层固定价差。
- E4：官方纸交易入门，不是实盘底盘。
- F9：最好懂。

只适合验证连接器，不能当高频底盘。

### `pmm_simple` — 59

V2 做市基类的薄封装（31 行）。多层买卖价差 + `PositionExecutor` + 三重屏障。现货可用市价再平衡库存。

- A4：定价用实时中间价，但基类默认 **`executor_refresh_time = 300s`**；成交后走仓位屏障，不是持续报价。
- B5：有 `position_rebalance_threshold_pct`，无经典 skew。
- C7：默认止损 3%、止盈 2%、45 分钟时限、止损后冷却 15s。
- D6：多层 + 金额百分比。
- E7 / F7：V2、参数可热更新，结构清楚。

要当高频用必须把刷新从 5 分钟改到数秒，并接受「每层是一笔带 TP/SL 的仓」而不是盘口常驻挂单。

### `pmm_v1` — 66

V2 移植旧版 PMM 核心：多层价差、`order_refresh_tolerance`、成交延迟、价格天花板/地板、**与 Cython 版同构的库存 skew**。用 `OrderExecutor` 挂限价，更接近传统做市。

- A7：默认 30s，容差可避免无意义撤单，可压到秒级。
- B8：`target_base_pct` + `inventory_range_multiplier`，买单 0–2×、卖单互补。
- C5：有价格带和成交延迟；**没有** 三重屏障。相对 V1 原版还缺挂起单、ping-pong、移动价格带。
- D7：多层 + 容差 + skew 调量；无 best bid/ask jumping、无手续费加价。
- E6：在维护的 V2 上，但是「半套原版」。
- F6：参数量适中。

要经典 skew、又想留在 V2，这是 `pmm_mister` 之下最合适的折中。

### V1 `pure_market_making` — 72

能力最全的报价引擎（Cython）：多层/拆档、库存 skew、`inventory_cost` 定价、挂起单、ping-pong、静态/移动价格带、最小价差自动撤、best bid/ask jumping、外部/API 定价、`take_if_crossed`、手续费加价。

- A8：刷新无下限（仍受 0.1s 时钟约束），可贴盘口优化。
- B8：skew + 库存成本价。
- C7：挂起单、价格带、成交延迟、`max_order_age`；无三重屏障。
- D9：这组里报价手段最多。
- E5：Foundation **不再主动维护 V1**，参数不能像 V2 controller 那样热更新。
- F5：旋钮多、扩展难。

高频贴合仍强，长期不建议新开 V1 实例。

### `pmm_mister` — 84

官方 README 的实盘示例（约 1700 行）。`tick_mode` 把价差换成最小价位跳动；刷新看时间和价格偏离；库存走 `min/target/max_base_pct`；成交后挂起，过 `effectivization` 才算进仓；可选按盈亏平衡禁止亏损减仓；可开全局 TP/SL。

- A8：盘口中间价 + tick 模式 + 价距刷新。默认刷新 30s、冷却 60s，要高频必须下调。
- B9：目标带 + 买卖分向 skew + 挂起单。
- C9：单笔 TP、全局 TP/SL 分档激活、盈亏平衡保护。
- D8：多层、距离容忍、LIMIT_MAKER。无波动率自适应、无盘口跳跃。
- E10：官方实盘入口，几乎所有关键参数 `is_updatable`。
- F5：参数互相耦合，配错会挂不住或囤库存。

**这组里最适合当秒级做市底盘。** 上线前把 `executor_refresh_time`、冷却、`tick_mode` 按品种 tick 和手续费改掉。

### `pmm_dynamic` — 57

在 `pmm_simple` 底座上，用 **3m K 线** 的 NATR 放大价差、MACD 平移参考价。

- A3：参考价是 K 线收盘平移，不是盘口中间价；默认同样 5 分钟刷新。这是中频自适应做市。
- B5：与基类相同的现货再平衡。
- C7：三重屏障同 `pmm_simple`。
- D8：波动率价差 + 趋势偏移，定价模型在这组 PMM 里最「聪明」。
- E6 / F6：多依赖 K 线质量和指标参数。

波动大、不想贴盘口时有用；不当高频。

### `grid_strike` — 54

给定 `start_price` / `end_price` / `limit_price`，价格在区间内启动一个 `GridExecutor`，默认每 3s 补一档，最多 2 张挂单。

- A6：执行层 3s 补单，但策略是区间网格，不是围绕中间价持续报价；出区间就不再新建执行器。
- B3：单边 `BUY` 或 `SELL`，无目标库存。
- C6：默认只有 0.1% 止盈，**默认没止损**；靠 `limit_price` 和区间约束。
- D5：网格边界静态，须人工改（可热更新）。
- E6 / F7：结构简单，区间选错就是单边风险。

适合震荡区间；区间外的趋势行情会闲置或单边堆积。

### `bollingrid` — 55

3m 布林带百分位给方向（`signal` = ±1），再用带宽系数算网格起止价和限价，`order_frequency` 默认 2s。

- A4：信号周期是分钟级（默认 100 根 3m ≈ 5 小时窗口），执行才是 2s。
- B4：选边后网格吃该方向，无组合库存目标。
- C7：方向性三重屏障 + 网格限价 + `max_open_orders=5`。
- D7：网格宽度跟波动走。
- E6 / F5：布林阈值 + 三个系数，`signal=0` 时不开网格。

高频只发生在「已经选出方向之后的补单」；选边本身不是高频。

### `quantum_grid_allocator` — 72

多资产组合网格。对照 `portfolio_allocation` 的理论仓与实际仓，偏离大则加大网格、进入只做多/只做空区；中间区双边对冲。默认 **1s K 线** 算布林宽度，有利方向 2s 补单、不利 5s，档间距默认 0.01%。

- A7：这组网格里最快；仍是网格，不是盘口最优报价。
- B9：组合再平衡 + 多空分区 + `max_deviation`，库存逻辑最完整。
- C7：TP/SL 比、limit 保护、单网格资金上限；叠加网格时路径难推理。
- D8：动态宽度、有利/不利频率、多交易对。
- E7：能力强，但不是官方「开箱实盘」那条路径。
- F3：参数面大，排障成本高。

要多币种、用网格做组合再平衡，选它；单币种贴盘口做市仍不如 `pmm_mister`。

## 怎么用这些分

| 目标 | 选 |
| --- | --- |
| 秒级单币种做市（V2） | `pmm_mister`（84），把刷新/冷却压到数秒，打开 `tick_mode` |
| 要经典 skew、少依赖仓位执行器 | `pmm_v1`（66），或暂用 V1 PMM（72，维护差） |
| 多币种网格再平衡 | `quantum_grid_allocator`（72） |
| 已知震荡区间 | `grid_strike`（54） |
| 波动率自适应、接受分钟级 | `pmm_dynamic`（57）或 `bollingrid`（55） |
| 学流程 / 纸交易 | `simple_pmm`（36） |

`pmm_simple`（59）是 V2 做市的骨架，正式跑建议直接上 `pmm_mister`，不要停在默认 5 分钟刷新的简单封装上。
